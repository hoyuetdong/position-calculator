# 富途查詢及止蝕監控

- US／HK 各保留一條交易推送連線。SDK 訂單／成交 callback 只排入要核對嘅 ID；唔直接使用推送股數落單，避免重複、亂序通知造成錯單。
- 推送喚醒原本持久化監控；斷線重連會重新核對。即使冇推送，每 10 秒仍有一輪後備檢查。
- 所有 app 發出嘅富途 SDK 讀取／交易命令經 `BrokerIO`；同帳戶、同接口共用 30 秒滑動額度，唔按市場／視窗分開計。SDK 內部連線及自動訂閱握手由 SDK 管理。
- 訂單及持倉平時讀 OpenD 快取，每 60 秒強制向富途核實。收到追蹤單推送或補止蝕前可優先更新，同一輪兩秒內合併；唔會繞過共用額度。
- 歷史訂單只喺當前清單搵唔到／核對提交意圖時讀取，同一份結果共用 5 分鐘；重連會清除歷史快取。行情快照共用 2 秒，歷史 K 線共用 5 分鐘，資金共用 30 秒。
- 普通請求預留兩個名額俾止蝕。限頻後按 30、60、120、240、300 秒退避；網絡／其他失敗亦有退避。安全核對失敗唔會用舊資料假裝成功。
- 本地額度未到而延後嘅止蝕，保留自動重試，唔計入交易失敗次數。交易指令從不由 gateway 自動重送；提交逾時仍交原有唯一 remark／持久化意圖核對。
- `GET /api/health`（需 API key）包括 `broker_io` 嘅 server_requests、cache_hits、deferred、rate_limits、cooling_interfaces，以及 push_contexts、push_received、last_push_at。計數自服務啟動開始，唔代表其他程式用量；有推送連線唔等於券商永不斷線。

測試：`venv/bin/python3 -m unittest discover -s backend/tests`。測試使用假券商，唔落真實單。正式環境驗證只做 API 健康及唯讀狀態核對；成交後補單仍由用戶原有交易流程觸發。
